# 旅行計画アプリ 画面構成・情報設計

要件定義書(requirements.md)の 5.1(機能一覧)・9章(データモデル)を元にした画面設計。

## UI刷新方針（確定 / 2026-08-18）
初期実装(MPA・機能ごとに個別ページ遷移)を実際に触った結果、以下の問題が判明したため、
アプリ全体を**フルSPA化**する方針に変更した。

- 機能画面(D〜H)間を行き来するたびに毎回C(旅行詳細トップ)を経由する画面遷移が煩雑
- ページ遷移のたびに白画面を挟む体験が、モバイル中心の想定利用シーンに合わない
- 企画メモ・しおりの入力の手間が大きい(下記参照)

このセクションが確定方針。旧来のMPA構成の記述は本ドキュメントの以降のセクションから
置き換える。

## 画面一覧
| 画面 | 役割 |
|---|---|
| A. 参加画面 | 名前＋合言葉を入力してグループに入る（入口）。新規グループ作成もここに置く。作成用合言葉はFirestore側で照合するため画面上には表示・保持しない（詳細はfirestore-design.md「グループ作成方法の方針」参照） |
| B. 旅行一覧画面 | グループのホーム。過去分も含めた旅行カード一覧＋新規旅行作成 |
| C. 旅行詳細（概要タブ） | 旅行名の表示・編集＋集合場所・割り勘リンクの直接編集欄。タブバーの基点 |
| 雑多メモタブ（新規） | 「みんなが書きなぐる」1つの共有テキスト欄。選択したテキスト範囲を「→企画メモへ」「→しおりへ」で振り分ける |
| D. 企画メモタブ | 旅行全体でみんなが書き込む、単一の共有テキスト欄（hackmd的な1枚メモ） |
| E. 行き先決めタブ | 候補地＋★投票＋ランキング |
| F. 日程調整タブ | 候補日ごとの○×△回答 |
| G. 宿泊タブ | 候補リスト＋確定宿泊（複数・期間付き）を1タブにまとめる |
| H. しおりタブ | 日付グルーピング＋時間順ソート。時間は午前/午後・時・分のプルダウン入力 |

## 画面遷移（SPA・ハッシュルーティング）
```
#/                              A. 参加(未参加時)。参加済みならB へ自動遷移
#/trips                         B. 旅行一覧
#/trips/:tripId                 C. 旅行詳細(概要タブ) ← タブバーの基点
#/trips/:tripId/scratch         雑多メモタブ
#/trips/:tripId/notes           D. 企画メモタブ
#/trips/:tripId/destinations    E. 行き先決めタブ
#/trips/:tripId/schedule        F. 日程調整タブ
#/trips/:tripId/lodging         G. 宿泊タブ
#/trips/:tripId/itinerary       H. しおりタブ
```
`#/trips/:tripId` 配下はすべて同一シェル(タブバー常設)内でのビュー切り替えであり、
**フルページ遷移は発生しない**。タブをタップすると該当ビューが再マウントされ、URLの
ハッシュ部分だけが変わる。ブラウザの戻る/進むはハッシュ履歴で自然に動作する。

A→B（参加/作成）のみ、状態遷移として「別ルートへ移る」感覚で残すが、これもフルページ
遷移ではなくルーター内の画面切り替えとして実装する。

## 設計判断
- 集合場所・時間、割り勘リンクは「単一の置き場」（要件9.3）のため独立タブを作らず、
  概要タブに直接埋め込む
- 宿泊は「候補」と「確定」をタブ分割せず1タブ(G)にまとめる。窮屈さを感じたら分割を
  検討する運用とする（2026-08-17 決定は維持）
- **新規グループ作成の防波堤の方式**：作成用合言葉はコードに埋め込まず、Firestore
  ルールの`get()`照合方式（詳細はfirestore-design.md「グループ作成方法の方針」参照）
- **雑多メモ→企画メモ/しおりへの振り分けは、ボタンタップ方式**（2026-08-18 決定）。
  ドラッグ&ドロップも検討したが、モバイル中心の想定利用シーン（要件6）でタッチ操作の
  ドラッグは実装コストが高く誤操作も起きやすいため、テキスト範囲を選択してボタンを
  タップする形にした（詳細は下記「雑多メモも単一共有テキスト」参照）
- **企画メモは単一共有テキスト**（2026-08-18 決定）。当初は投稿者名付きの個別メモを
  積み重ねる一覧方式だったが、「hackmdのように1枚に自由に書き足していく」体験を
  求める声を受け、旅行1件につき1つの共有テキストフィールドに変更した。同時編集時の
  競合（後勝ち上書き）は許容する（Google Docs的な文字単位の共同編集までは求めない。
  要件6「同時編集」の非機能要件が元々そのレベルの許容を明記している）
- **雑多メモも単一共有テキスト**（2026-08-18 決定・追加変更）。当初は「投稿者名付きの
  個別メモを積み重ねる一覧＋1件ずつ振り分けボタン」の設計だったが、雑多メモは
  「みんなでどんどん書き足していく、一番よく使う置き場」という位置づけであるため、
  企画メモと同じく旅行1件につき1つの共有テキスト（`scratchText`）に変更した。これに伴い
  振り分けボタンの対象も「1件のメモ」から「テキストエリア内で選択した範囲」に変わった。
  テキストの範囲選択はドラッグ&ドロップとは異なる標準的な操作であり、選択後にボタンを
  タップする点は変わらないため「ボタンタップ方式」自体は維持される。「→企画メモへ」は
  選択範囲を`planningNotesText`の末尾に追記し`scratchText`側は選択範囲のみ削除、
  「→しおりへ」は選択範囲を`itineraryItems`の`title`として、日付選択のみの簡易フォームを
  挟んで新規作成し、同様に`scratchText`側は選択範囲のみ削除する（詳細は
  firestore-design.md「雑多メモの振り分け方式の再設計」参照）
- **しおりの時間入力はプルダウン3つ**（2026-08-18 決定）。`<input type="time">`の
  ネイティブUIが使いにくいとの声を受け、「午前/午後」「時(0〜12)」「分(00/15/30/45)」
  の3つのセレクトボックスに変更する。保存されるデータ形式("HH:MM"文字列)自体は
  変わらないため、firestore-design.mdのスキーマ変更は無い
- **レイアウトも各画面のHTML構造・CSSから作り直す**（2026-08-19 決定）。`16`で配色等の
  トークンを変更したのみでは「安っぽさ」は解消しないとの評価を受け、SVGアイコン導入・
  タイポグラフィ階層の強化・余白のメリハリ・追加フォームの折りたたみ化・トランジション
  追加などに踏み込む（詳細はdocs/ROADMAP.md「第3期: レイアウト刷新」参照）。画面構成・
  画面遷移（本ドキュメントの「画面一覧」「画面遷移」）自体は変更しない。絵文字による
  簡易アイコン代用は不採用（見た目の一貫性を欠くリスクがあるため）
