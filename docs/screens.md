# 旅行計画アプリ 画面構成・情報設計

要件定義書(requirements.md)の 5.1(機能一覧)・9章(データモデル)を元にした画面設計。

## 画面一覧
| 画面 | 役割 |
|---|---|
| A. 参加画面 | 名前＋合言葉を入力してグループに入る（入口） |
| B. 旅行一覧画面 | グループのホーム。過去分も含めた旅行カード一覧＋新規旅行作成 |
| C. 旅行詳細画面（トップ） | その旅行のダッシュボード。各機能へのカードリンク＋集合場所・割り勘リンクはこの画面に直接埋め込み表示 |
| D. 企画メモ画面 | やりたいこと出しの一覧 |
| E. 行き先決め画面 | 候補地＋★投票＋ランキング |
| F. 日程調整画面 | 日付ごとの○×△カレンダー |
| G. 宿泊画面 | 候補リスト＋確定宿泊（複数・期間付き）を1画面にまとめる |
| H. しおり画面 | 日付グルーピング＋時間順ソート |

## 画面遷移
```
A(参加)
  └─ 参加/作成 ──▶ B(旅行一覧)
                       │
              新規作成 or 既存タップ
                       ▼
                  C(旅行詳細トップ)
              ┌────┬────┬────┬────┐
              ▼    ▼    ▼    ▼    ▼
              D    E    F    G    H
```
各機能画面は「戻る」でCに復帰。深さはA→B→C→機能画面の最大2階層。

## 設計判断
- 集合場所・時間、割り勘リンクは「単一の置き場」（要件9.3）のため独立画面を作らず、Cに直接埋め込む
- 宿泊は「候補」と「確定」を画面分割せず1画面(G)にまとめる。使ってみて窮屈さを感じたらタブ分割等を検討する運用とする（2026-08-17 決定：まずはシンプルに作り、改善は使用後の反復に委ねる）
