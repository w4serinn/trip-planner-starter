## 第3期: レイアウト刷新

`16`でトークン(配色・角丸等)は変更したが、人間から「レイアウトも汚い」との評価を受け、
2026-08-19に人間とのチャットで追加方針を決定。トークンいじりだけでなく、各画面のHTML
構造・CSSを作り直すレベルまで踏み込む(データモデル・Firestore構造・`docs/screens.md`の
画面構成・遷移は不変。あくまで既存画面の内部レイアウト・視覚表現の作り直し)。

背景・調査結果:
- 「安っぽく見える」の主因は、絵文字的な装飾の不足ではなく、①SVGアイコンが無い
  ②タイポグラフィに階層が無い ③余白のリズムが均一 ④画面ごとの表情が全部同じ
  (どのタブも「見出し→フォーム→リスト」の判で押した構成) ⑤状態変化にトランジションが
  無く一瞬で切り替わる、の5点と分析した。
- Wanderlog(旅行プランナー)・TimeTree(共有カレンダー)等の既存アプリを調査し、
  「追加フォームを常時表示せず折りたたむ」「一覧をカード/タイムライン的に見せる」等の
  パターンを参考にした。絵文字によるアイコン代用は不採用(OS/ブラウザで見た目が
  バラバラになり、狙いと逆に安っぽく見えるリスクがあるため)。

`17. 共通基盤の整備`・`18. 画面ごとのレイアウト刷新`は全て完了済み
(詳細はdocs/roadmap-done.md参照)。トークン・タイポグラフィ・カード/ボタンの質感刷新、
SVGアイコンセット(`src/icons.js`)、折りたたみフォームパターン(E〜Hの追加フォーム)、
A(参加)のカード分離、B(旅行一覧)のカード情報拡充、C(概要)の表示/編集モード統一、
D・雑多メモのカード化、E(行き先決め)のランキング視覚化(順位バッジ+スコアバー)、
G(宿泊)の候補/確定宿泊の区分、H(しおり)のタイムライン風表示まで全て完了。

## 第4期: PC(広い画面)向けレスポンシブ対応

`docs/requirements.md`「プラットフォーム: モバイルブラウザ中心、レスポンシブ対応」を
満たせていない点として、2026-08-19に人間から指摘。現状`.page { max-width: 480px; }`が
画面幅によらず常に固定されており、PCの広い画面では左右に余白ができて物足りない見た目に
なっていた。人間との相談の結果、**ウィンドウ幅に応じて動的に、広い画面ではカード一覧を
複数カラムのグリッド表示にする方式**で確定(単純な固定幅拡大ではなく、レスポンシブな
複数カラムレイアウトを採用)。データモデル・Firestore構造・`docs/screens.md`の画面構成・
遷移は不変。あくまでCSS(メディアクエリ)による表示側の対応。

### 19. 共通基盤: ブレークポイント・幅の可変化
- [ ] (S) `pages/shared.css`の`.page`に、画面幅に応じた`max-width`のメディアクエリを
      追加する(例: 768px未満は現状の480pxのまま、768px以上は700px程度、1024px以上は
      さらに広く)。具体的なブレークポイント・数値は実装時に調整してよい

### 20. リスト系画面のグリッド化
広い画面では、カードが縦一列に並ぶだけでは間延びするため、該当画面のカード一覧コンテナを
CSS Gridに変更し、`grid-template-columns`をメディアクエリで画面幅に応じて変える
(モバイル幅では従来通り1列)。
- [ ] (S) B(旅行一覧)画面: 旅行カード一覧をグリッド化
- [ ] (S) E(行き先決め)画面: 候補地カード一覧をグリッド化(★投票・スコアバー等の
      中身のレイアウトは変更しない)
- [ ] (S) F(日程調整)画面: 候補日カード一覧をグリッド化
- [ ] (S) G(宿泊)画面: 宿泊候補・確定宿泊、それぞれのカード一覧をグリッド化

### 21. その他画面の広い画面での調整
- [ ] (S) C(概要)・雑多メモ・企画メモ画面: グリッド化はせず、`19`の幅拡大の恩恵を
      受けるのみで良いか、追加の調整が要るか実装時に確認する(雑多メモ・企画メモの
      `<textarea>`は横に広い方が使いやすいと想定される)
- [ ] (S) H(しおり)画面: タイムライン表示は時系列を表す都合上1カラムのままが自然と
      考えられるため、グリッド化はせず据え置く方針で良いか実装時に再確認する

## 第5期: 配色・タイポグラフィの統一感強化

2026-08-19、人間から「デザインがまだ単調」との指摘を受け、複数の参考サイト
(sankoudesign.com「旅行・観光」カテゴリ、w4serinn.github.io/yamagata_trip、
miricanvas「旅のしおり」テンプレート、design-library.jp「お問い合わせ」UI集、
g-mark.org受賞ギャラリー)を調査した上で方針を確定。「和風」等の特定スタイルへの
転換ではなく、**既存の明るい青ベース配色を活かしつつ、体系立った統一感を持たせる**
方向で合意(配色の全取っ替えは4回目になるため、既存資産を活かす)。

背景・調査結果:
- yamagata_tripの実CSSを直接確認したところ、フォントペアリング・伝統色による
  体系的な配色・CSSのみのテクスチャ(画像不使用)・番号バッジ・全面塗りセクションに
  よるリズムづけが、写真無しでも「単調に見えない」ことに効いていると判明
- design-library.jp自体のCSSから、ピル型ボタン(`border-radius:50px`、
  パディング`9-10px 14-16px`)・青みを帯びたカード影(`rgba(0,0,128,...)`系)の
  具体的な数値を採取
- miricanvasの「旅のしおり」テンプレートは「ベース+アクセント2〜3色に絞る」
  「情報をブロックごとに枠線で区切る」という、既存のカード主体の設計と親和性の高い
  方針を採用している
- g-mark.orgの受賞デザイン(id:14776)は「AIカレンダー/日程調整ツール」という
  同カテゴリの製品だったが、JS描画のため詳細は自動取得できず、人間が直接確認したい
  場合は別途ブラウザで見る必要がある

### 23. デザイントークンの拡充
- [ ] (S) Google Fontsの「Zen Kaku Gothic New」(400;500;700;900)を
      `styles/tokens.css`に`@import`で追加し、`--font-family-base`をこれに変更
      (フォールバックとして既存の"Hiragino Sans"等は残す)。`--font-weight-heading`を
      700→900、`--font-weight-subheading`を600→700に強化し、太さのジャンプ率を
      大きくする
- [ ] (S) `--color-primary`(青)を基準に、同系統の深色バリエーション
      `--color-primary-deep`(藍のような、青をさらに沈めた濃紺系の色。具体的な値は
      実装時に調整)を新規追加する。ヘッダー等、一部セクションの背景に使う
- [ ] (S) 差し色として、青と調和する落ち着いた緑を1色新規に検討する
      (既存の`--color-success`と統合できないか、独立させるべきかも合わせて検討する)
- [ ] (S) `--shadow-card`を、現状の中立グレー系の影から、青みを帯びた影
      (`rgba(29, 78, 216, ...)`系。design-library.jpの実例を参考)に変更し、
      青ベース配色との統一感を強める
- [ ] (S) ピル型(完全な丸み、`border-radius: 999px`程度)のボタン/バッジ用トークン

### 24. ヘッダーのテクスチャ強化
- [ ] (M) `index.html`のアプリヘッダー(「旅行計画アプリ」の見出し部分)に、

      yamagata_tripの`.hero::after`を参考)。現状の「白背景に黒文字」の単調な
